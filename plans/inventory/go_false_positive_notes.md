# Go → Crystal False Positive Notes

The `go_port_remaining_heuristic.tsv` file lists 3600 Go items as "missing" (status=missing,
notes=heuristic-filter). These are **nearly all false positives** caused by naming-convention
mismatches between Go's CamelCase and Crystal's snake_case, plus structural differences in
how the two languages handle method dispatch and code generation.

## Naming Convention Mappings

| Go Convention | Crystal Convention | Example Go → Crystal |
|---|---|---|
| `CamelCase` methods/types | `snake_case` methods/types | `SetBlockedURLs` → `set_blocked_urls` |
| `Is(err error) bool` | `is?(err : Exception.class) : Bool` | `CoveredError.Is` → `CoveredError#is?` |
| `MustMethodName` (explicit) | `must_method_name` (explicit or `method_missing` macro) | `MustNavigate` → `must_navigate` |
| `GetField` accessor | `field` (Crystal property) | `GetFlags` → property `flags` |
| Boolean checkers `IsX()` | Predicate `x?` | `IsNavigation()` → `navigation?` |

## Category Analysis

### 1. CDP Constants (1627 items) — ALL FALSE POSITIVES
Auto-generated by `pdlgen` from Chrome DevTools Protocol definitions. The Crystal
equivalents exist in `src/cdp/*/types.cr` and `src/cdp/*/events.cr`. The heuristic
cannot map Go constant names to Crystal constant names due to different module
structure and `alias` usage.

### 2. CDP Structs (1339 items) — ALL FALSE POSITIVES
Auto-generated CDP type/event/command structs. Crystal equivalents exist under
`src/cdp/*/` with the same logical structure but different naming (e.g.
`AccessibilityAXNode` → `Cdp::Accessibility::Node`).
